# Naming a taste

Liking something is not a brief. This turns a pile of references into a look the user picked, with a reason behind every choice. Done this way, the pick comes down to a handful of short questions instead of an argument.

## 1. Gather and board

- Pull frames from what the user saves: reels, film edits, sites, carousels, their own best screen. Note the timestamp of each frame.
- One note per input with three columns: **what it taught**, **what I take**, **what I leave**. The leave column matters as much as the take: it stops a reference's baggage (its licence, its subject, its effects) coming along.
- Group frames into boards by quality, not by source: light, figure, dark, colour, type, objects, and one board of what the user rejects. A board of their own site's tells is part of the reject board.

Done when every input has a note and every board has at least three frames from different sources.

## 2. Write the profile

- Say the taste in plain words, a short paragraph.
- Pin every claim to frames on a board. A claim with no frame comes out.
- Look for the shape that turns up in inputs that share nothing else. That is usually what the user actually likes, and it is rarely the subject. (Five unrelated inputs sharing one arc of light meant the user liked the arc, not the film it came from.)
- Measure what can be measured (section "Measure it" in SKILL.md) instead of asserting it.

## 3. Rulebook

Merge rules from every source into one numbered list, grouped by colour, type, layout, texture, motion, interaction, copy, platform. Fold duplicates into one line with every source in brackets. Then the fight table: each clash, the pick, and why. Then audit the current site against the numbered rules, with file and line where possible and screenshots at 1080, 4K, ultrawide, tablet and phone.

## 4. The direction sheet

One HTML page, opened in a browser, that the user decides from:

1. **Baseline first.** The site as it is today, captured, on the same surfaces as every direction.
2. **What every direction keeps.** The invariants, so the user only judges what changes.
3. **Directions, ranked**, each drawn on the same surfaces (home, index, detail page, link preview, ultrawide, phone, plus any tool page). Per direction:
   - a name and a one-line description
   - the palette as a 60-30-10 bar, each hex labelled with its role, contrast ratios printed
   - the type pair, with its licence
   - **from**: which references it comes from
   - **why**: the case for it
   - **cost**: the honest risk of choosing it
4. **Axes pulled apart.** On the leading direction, vary one thing per row (render style, texture at real strength, texture boosted, the hero object, type pairs, the accent) so a single choice can be seen alone.
5. **Rules and numbers**: the fight table and measured costs.
6. A **live view** where the user can mix axes, and a "pick this" control that reports back.

Type pairs are shown on the real name, real copy, a real button and a real data label, never on lorem.

## 5. Decide

Ask one question at a time, my pick first, with the sheet open. Record each answer with its date in the research doc, and redraw the sheet when an answer changes what follows. Watch what the user does in the live view as well as what they say; when there is no voice on a recording, say that the reading is mine.
